## Dependency notes

- **Plan 016** (whitelist localhost security guard) depends on Plan 015 for clean test verification.
- **Plans 017 & 018** (worker retry and upload stream cleanup) resolve backend worker and upload stability issues.
- **Plan 023** (CategoryManager modular decomposition) supersedes Plan 014: commit `4a87fd5` extracted three small components but left `CategoryManager.jsx` at 2,446 lines; Plan 023 completes the modular decomposition into `<500` lines backed by tests from Plan 013.
- **Plan 026**'s original GTK/libadwaita approach was superseded by the working
  Dioxus Native/Blitz implementation. Its protected playback, WGPU video path,
  Debian/RPM packaging, and Flatpak run were validated; MPRIS remains separate.
- **Plan 027** depends on that existing Dioxus implementation and redesigns only
  its presentation plus typed artwork/dashboard data. It must not disturb the
  proven playback, Tokio, WGPU, or packaging paths.
- **Plan 028** depends on the existing Dioxus playback owner from Plan 026 and
  reuses its idempotent playback and queue paths. It does not depend on Plan
  027's remaining visual acceptance work.
- **Plans 029–037** are all independent of each other and can be executed in any order or in parallel.
- **Plan 039** defines the safe exclusive-session holder contract and must land
  before **Plan 040**, which consumes that contract in all three clients.
- **Plan 041** depends on Plans 039–040 and replaces their five-second HTTP
  heartbeat/status polling with an authenticated WebSocket push channel across
  server, Web, Mobile, and Desktop. HTTP remains reconnect/legacy fallback.
- **Plan 042** follows Plan 041 because both modify Mobile protected-session
  ownership in `player-context.jsx` and `full-player.jsx`; its late async
  source cleanup must be applied to the final WebSocket-aware lifecycle.
- **Plan 043** is functionally independent of Plans 039–042 (desktop-only
  local mode, no server or mobile changes), but it shares
  `desktop/src/ui/mod.rs` with Plan 040 — serialize those two and re-run the
  drift check.
- **Plan 044** (macOS cross-compile + DMG) is ordered after Plan 043 so the
  first mac release ships the offline local-folder fallback; no technical
  dependency.

## Findings considered and rejected

- *Migrate entire monorepo to TypeScript*: Rejected — JS ESM is intentional by design per AGENTS.md; JSDoc / `checkJs` via `jsconfig.json` is preferred and lower risk without breaking build pipelines.
- *Replace IP-based authorization with user login accounts*: Rejected — IP-based whitelist is the core architectural principle of DogMedia.
- *Remove Redis or SQLite*: Rejected — Redis (queues, active sessions) and SQLite (mobile offline) are settled architectural decisions.
- *Complete architectural rewrite of GlobalPlayer*: Rejected — High risk for core audio/video streaming engine; incremental hook extraction is preferred once playback characterization tests are in place.
- *Hardcoded DB password fallbacks (SEC-09)*: Rejected — `AGENTS.md` documents `PFS_DB_PASSWORD` with default `pfs_secret` as intentional self-hosted convenience.
- *Cap byte range chunk size (PERF-07)*: Deferred — MED risk of breaking HTML5 video seeking compatibility outweighs benefit at current private server scale.
- *Correlated variant subqueries (PERF-06)*: Not worth doing — subqueries bounded by encoding tiers (3–4 per media), not by media count.
- *React version mismatch (DEP-01)*: Cosmetic — Expo 57 pins 19.2.3 for mobile; web 19.2.7 is compatible.
- *Peer dependency warnings (DEP-02)*: Low signal — not causing runtime issues.
